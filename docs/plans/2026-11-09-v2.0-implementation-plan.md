## 3. 并发设计与测量基线（复用 chan-bench-cj 已验证结论）

> 来源：[`chan-bench-cj/README.md`](../../../chan-bench-cj/README.md) 与 `chan-bench-cj/docs/benchmark-report.md`
> （§2.3 测量口径、§7 LSM-KV 引擎落地验证、§8 负结果、§9 编译器版本对照）。
> **这些数字已在 16 核实测，不要在 2.0 里重做同一批实验；直接引用口径与结论。**

### 3.1 结论摘要（可直接引用）

| 做法 | 成本 | 相对最优 |
|---|---|---|
| 静态分片分派（零同步） | 0.23 ns/项 | 1x |
| 原子抢单分派（`AtomicInt64.fetchAdd`） | 4.6 ns/项 | 20x |
| 无锁 SPSC 环形（逐条，cap=1024） | 39.0 ns/条 | 170x |
| 抑制唤醒的单锁环形 `ring2`（逐条，cap=1024） | 42.7 ns/条 | 186x |
| Go 原生 `chan`（对照，cap=1024） | 25.6 ns/条 | 111x |
| 共享队列分派（Go worker pool 写法） | 115.6 ns/项 | 500x |
| **批量交接（每批 64 条）** | **0.6 ns/元素** | — |
| **一次「提交→等完成→被唤醒」往返** | **1130–1610 ns**（Go 170 ns） | — |

杠杆排序：**批量交接（48–73x）≫ 抑制无效唤醒（1.3–2.1x）> 换队列实现**。只要模型要求「发出去 → 等对方做完 → 被唤醒」，每次就要付 ~1.1–1.6 µs；能不用这种模型就别用。

已在本仓落地（报告 §7）：`CloseableBlockingQueue` 改 `ring2` 后全量 **375/375**，`txn_queue_perf` 两版二进制交替 9 轮端到端写吞吐 `4567 vs 4956 ns/txn`（**−7.8%**，配对 9/9 全胜），并修掉「队满时 `close()` 唤不醒阻塞生产者」的挂起缺陷。

### 3.2 对 2.0 各阶段的硬约束

1. **阶段 4 的 group commit 不换队列实现**：`ring2` 已经吃掉了「抑制无效唤醒」那一档（1.3–2.1x）；组提交的收益只能来自**减少「提交→等完成→被唤醒」次数**（每次 ~1.1–1.6 µs）——把 N 个请求合并成「一次 WAL 写 + 一次 msync + 一次批次完成信号」，而不是再换队列/加无锁结构（边际收益低且会破坏 close 契约）。
2. **不要把批次切碎**：批量摊薄（0.6 ns/元素 vs 39–42.7 ns/条）是最大的杠杆。WriteBatch 自动切分要「大而少」，按 `maxBatchSize` 上限切，不要为了单笔延迟切小；`Config` 里给上限而不是目标批大小。
3. **不新增「提交→等完成」往返**：每请求 `done()` 只允许一次（v1.6.22 已用 `write_pipeline_done_once_test` 钉住）；组提交沿用同一批完成信号，不得为「等整批落盘」再引入一次同步。
4. **不要重复已验证的负结果**（报告 §8）：`WriteRequest` 复用 `Semaphore`（-39% 微基准但端到端不显著，Welch t=-0.26）与「单级写路径」(-1.5%，破坏收集/执行解耦) 都已被否决，2.0 不要重开。
5. **压测场景固定**：`txn_queue_perf` 8 线程 × 5000 事务 × 单键（与报告 §7 同口径），另加 `keysPerTxn=8/64` 两组（批量摊薄对照）；数据目录**必须在真实盘**（`/tmp` 是 tmpfs，会让 mmap/IO 对照失真）。
6. **测量方法**（报告 §2.3 + §7.3）：
   - 两版二进制**交替**各 ≥9 轮，报告均值 + 中位数 + 逐轮配对胜负 + Welch t；
   - **禁止**「取各实现最佳轮」判定微秒级差异（会掩盖结论：同一组数据按 best-round 只差 0.5%）；
   - 只计时核心循环，预热一轮 `n/10`；元素类型/迭代次数两侧同口径；
   - 队列/提交类改动同时跑 `-j 4` 正确性回归与 `-j 16` 压力位。
7. **编译器版本必须同机对照**：报告 §9 —— 1.2.0 的队列吞吐比 1.1.3 慢 2–9%，跨版本数字不可直接比较。

### 3.3 并发正确性测试清单（阶段 4/5 必带）

- 每请求 `done()` 只一次（既有 `write_pipeline_done_once_test`）；
- 批次中途异常：整批 `markFailed` + `finally` 统一 `done()`；
- 批跨 WAL 换段；批中崩溃只恢复前缀；
- `syncWrites=true`：批尾一次 msync 后，批内所有提交均可见；
- close 期间的阻塞生产者/消费者（`testBlockedProducerFailsOnClose` 类）；
